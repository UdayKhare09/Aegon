Aegon provides a high-performance, RFC 6455 compliant WebSocket implementation directly integrated into its pluggable I/O engine (Linux `io_uring`, edge-triggered `epoll`, and Windows `IOCP`) and C++23 coroutine architecture.

It features **5-tier SIMD and SWAR hardware unmasking** (AVX2 → SSE2/NEON → SWAR → scalar tail), **zero-copy frame parsing**, **in-place payload transformation**, **automatic backpressure management via `send_all`**, and **high-throughput frame batching**.

---

## Route Registration Patterns

Aegon offers several route registration styles depending on your application requirements:

### 1. Default Fast-Path Echo Endpoint
When no callback is provided, Aegon automatically registers an ultra-low latency, zero-allocation echo handler that batches frames directly into contiguous outbound buffers:

```cpp
// Both declarations are identical:
server.router().ws("/ws");
server.router().ws_echo("/echo");
```

### 2. Message-Level Echo Callback (`WebSocketEchoHandler`)
Use this when you want to intercept every incoming message and run lightweight asynchronous transformations before responding:

```cpp
#include <aegon/Server.h>

using namespace aegon;
using namespace aegon::http::websocket;

server.router().ws("/transform", [](WebSocket& ws, Message msg) -> Task<void> {
    if (msg.is_text()) {
        std::string reply = "Received: " + std::string(msg.text());
        co_await ws.send_text(reply);
    } else if (msg.is_binary()) {
        co_await ws.send_binary(msg.binary());
    }
});
```

### 3. Connection-Level Lifecycle Handler (`WebSocketHandler`)
For interactive applications (such as chat rooms, real-time telemetry, collaborative editors, and gaming servers), register a connection handler where you bind individual event callbacks:

```cpp
#include <aegon/Server.h>

using namespace aegon;
using namespace aegon::http::websocket;

server.router().ws("/chat", [](WebSocket& ws) -> Task<void> {
    // 1. Connection established
    std::println("Client joined {} on fd {}", ws.path(), ws.fd());

    // 2. Register callbacks on the connection instance
    ws.on_text([](WebSocket& ws, std::string_view text) -> Task<void> {
        co_await ws.send_text("Echo: " + std::string(text));
    });

    ws.on_binary([](WebSocket& ws, std::span<const uint8_t> data) -> Task<void> {
        co_await ws.send_binary(data);
    });

    ws.on_close([](WebSocket& ws, CloseCode code, std::string_view reason) -> Task<void> {
        std::println("Client left. Code: {}, Reason: {}", static_cast<uint16_t>(code), reason);
        co_return;
    });

    co_return;
});
```

### 4. Router-Level Binding
You can also register WebSocket routes on a standalone `Router` instance before attaching it to the `Server`:

```cpp
Router router;
router.ws("/feed", feed_handler);
router.ws_echo("/feed/echo");

Server server(std::move(router));
```

<Callout type="info" title="Automatic 426 Upgrade Required Fallback">
When a WebSocket route is registered, Aegon automatically configures an HTTP `GET` handler for that path that returns `426 Upgrade Required` with the `Upgrade: websocket` header if a standard HTTP client connects without valid WebSocket handshake headers.
</Callout>

## The `WebSocket` Connection Object

When a client upgrades to a WebSocket session, an instance of `aegon::http::websocket::WebSocket` represents the active connection:

### Connection State & Properties

```cpp
// Returns true if the connection and underlying transport are active
bool active = ws.is_open();

// Underlying OS socket file descriptor
int fd = ws.fd();

// Request path that initiated the upgrade (e.g., "/chat")
std::string_view path = ws.path();

// Underlying transport protocol (TransportProtocol::Http1 or TransportProtocol::Http3)
TransportProtocol proto = ws.transport_protocol();
```

### Sending Messages

All transmission methods return an asynchronous `aegon::core::Task<void>`:

```cpp
// 1. Send Text Frame (Opcode::Text)
co_await ws.send_text("Hello from Aegon!");

// 2. Send Binary Frame (Opcode::Binary) from std::span or byte container
std::vector<uint8_t> bytes = {0x01, 0x02, 0x03, 0x04};
co_await ws.send_binary(bytes);

// 3. Send Frame with explicit Opcode
co_await ws.send("custom payload", Opcode::Text);

// 4. Send Ping Control Frame (payload maximum 125 bytes)
co_await ws.send_ping("heartbeat");

// 5. Send Pong Control Frame (usually automatic, but can be triggered manually)
co_await ws.send_pong("heartbeat");

// 6. Graceful Closing Handshake
co_await ws.close(CloseCode::Normal, "Goodbye");
```

## Event Callbacks & Hooks

Event handlers can be assigned dynamically to the `WebSocket` object:

### `on_text`
Invoked when a complete, unmasked text frame (`Opcode::Text`) is received:
```cpp
ws.on_text([](WebSocket& ws, std::string_view text) -> Task<void> {
    // text is valid for the duration of this coroutine
    co_await ws.send_text(text);
});
```

### `on_binary`
Invoked when a complete, unmasked binary frame (`Opcode::Binary`) is received:
```cpp
ws.on_binary([](WebSocket& ws, std::span<const uint8_t> data) -> Task<void> {
    // data is a non-owning span over the unmasked bytes
    co_await ws.send_binary(data);
});
```

### `on_message`
Unified callback invoked for **both** Text and Binary frames:
```cpp
ws.on_message([](WebSocket& ws, Message msg) -> Task<void> {
    if (msg.is_text()) {
        std::println("Text message: {}", msg.text());
    } else if (msg.is_binary()) {
        std::println("Binary message: {} bytes", msg.binary().size());
    }
    co_return;
});
```

### `on_ping`
Invoked when a ping frame is received. Aegon automatically transmits the RFC 6455 pong reply, and then triggers this hook:
```cpp
ws.on_ping([](WebSocket& ws, std::string_view payload) -> Task<void> {
    std::println("Ping received with payload: {}", payload);
    co_return;
});
```

### `on_close`
Invoked when the client initiates a close handshake or the session terminates:
```cpp
ws.on_close([](WebSocket& ws, CloseCode code, std::string_view reason) -> Task<void> {
    std::println("Session closed. Code: {}, Reason: {}", static_cast<uint16_t>(code), reason);
    co_return;
});
```

### `on_error`
Invoked if an unexpected exception occurs during connection processing:
```cpp
ws.on_error([](WebSocket& ws, const std::exception& e) {
    std::println(stderr, "WebSocket error on fd {}: {}", ws.fd(), e.what());
});
```

## The `Message` Object

Header: `<aegon/http/websocket/WebSocket.h>`

The `Message` class provides a unified non-allocating interface over incoming frames:

```cpp
class Message {
public:
    std::string_view payload() const noexcept;          // Raw payload view
    std::string_view text() const noexcept;             // String view of payload (for text frames)
    std::span<const uint8_t> binary() const noexcept;   // Byte span of payload (for binary frames)
    Opcode opcode() const noexcept;                     // Frame Opcode
    bool is_text() const noexcept;                      // True if Opcode::Text
    bool is_binary() const noexcept;                    // True if Opcode::Binary
};
```

## Opcodes & Control Frames

Defined in `aegon::http::websocket::Opcode`:

| Enum | Value | Description |
|---|---|---|
| `Opcode::Continuation` | `0x0` | Continuation frame for fragmented messages. |
| `Opcode::Text` | `0x1` | UTF-8 text message. |
| `Opcode::Binary` | `0x2` | Binary data message. |
| `Opcode::Close` | `0x8` | Connection close control frame. |
| `Opcode::Ping` | `0x9` | Ping control frame. |
| `Opcode::Pong` | `0xA` | Pong control frame. |

```cpp
// Helper function to test control frames (Close, Ping, Pong)
bool is_ctrl = is_control_opcode(msg.opcode());
```

## Close Codes (`CloseCode`)

Defined in `aegon::http::websocket::CloseCode`:

| Enum | Value | Meaning |
|---|---|---|
| `CloseCode::Normal` | `1000` | Normal closure; the connection successfully completed its purpose. |
| `CloseCode::GoingAway` | `1001` | Endpoint is going away (server shutting down or client navigating away). |
| `CloseCode::ProtocolError` | `1002` | Protocol violation detected by endpoint. |
| `CloseCode::UnsupportedData` | `1003` | Data format not acceptable (e.g., text received when expecting binary). |
| `CloseCode::NoStatusReceived` | `1005` | Reserved: No status code present in close frame. |
| `CloseCode::AbnormalClosure` | `1006` | Reserved: Connection closed abnormally without a close frame. |
| `CloseCode::InvalidFramePayload` | `1007` | Inconsistent payload data (e.g., invalid UTF-8 in text frame). |
| `CloseCode::PolicyViolation` | `1008` | Generic policy violation. |
| `CloseCode::MessageTooBig` | `1009` | Message payload exceeded maximum allowed size. |
| `CloseCode::MandatoryExtension` | `1010` | Client expected an extension not negotiated. |
| `CloseCode::InternalError` | `1011` | Unexpected internal server error. |

## Configuration & Resource Limits (`WebSocketConfig`)

Aegon provides a granular configuration object `WebSocketConfig` defined in `<aegon/http/ServerConfig.h>` to defend against memory exhaustion DoS attacks and configure connection heartbeats:

```cpp
#include <aegon/Server.h>
#include <aegon/http/ServerConfig.h>

using namespace aegon;
using namespace aegon::http::websocket;

int main() {
    Server server;

    WebSocketConfig ws_cfg;
    ws_cfg.max_message_size = 8 * 1024 * 1024;  // 8 MB max message size -> 1009 MessageTooBig
    ws_cfg.max_frame_size = 4 * 1024 * 1024;    // 4 MB max single frame limit
    ws_cfg.require_masked_frames = true;        // RFC 6455 §5.1 client-to-server masking
    ws_cfg.auto_ping_interval_sec = 30;         // Heartbeat every 30s (0 = disabled)
    ws_cfg.ping_timeout_sec = 10;               // Reaps connection if no pong within 10s
    ws_cfg.initial_buffer_capacity = 4096;      // Ingest/batch buffer pre-allocation in bytes

    // Apply configuration to Server
    server.websocket(ws_cfg);

    // Or configure fluently:
    server.ws_max_message_size(8 * 1024 * 1024)
          .ws_max_frame_size(4 * 1024 * 1024)
          .ws_require_masked_frames(true)
          .ws_auto_ping_interval(30);

    server.listen(8080);
    server.run(8);
}
```

### Protection Against Memory Exhaustion (RFC 6455 §7.4.1)

If a malicious client streams an oversized frame or sends a frame whose header specifies a `payload_len` greater than `max_frame_size` or `max_message_size`, Aegon immediately:
1. Rejects the payload without buffering it into memory.
2. Sends a graceful Close control frame with status code `CloseCode::MessageTooBig` (`1009`).
3. Closes the underlying socket, defending the server against memory exhaustion and OOM crashes.

### Masking Toggle for Reverse Proxies

By default, `require_masked_frames = true` per RFC 6455 §5.1. Unmasked frames on TCP are rejected with `CloseCode::ProtocolError` (`1002`).

When Aegon is deployed behind an API gateway or internal reverse proxy (such as Envoy, Nginx, or Traefik) that terminates TLS and unmasks WebSocket client traffic, set `ws_require_masked_frames(false)` to seamlessly accept unmasked client frames.

## Low-Level Framing Utilities

For developers writing custom protocol adapters or benchmarking utilities, Aegon exposes low-level framing functions in `aegon::http::websocket`:

### Header Parsing & Serialization
```cpp
#include <aegon/http/websocket/WebSocketFrame.h>

// Parse frame header from raw buffer
FrameHeader header;
FrameParseResult res = parse_frame_header(buffer, header);
// Returns: FrameParseResult::Complete, FrameParseResult::NeedMoreData, or FrameParseResult::ProtocolError

// Serialize frame header (2, 4, or 10 bytes)
std::array<uint8_t, 10> out_header{};
size_t hlen = serialize_frame_header(Opcode::Text, payload_len, out_header.data(), /*fin=*/true);
```

### In-Place Tiered SIMD Unmasking
```cpp
// Hardware accelerated (AVX2 -> SSE2/NEON -> SWAR -> bitwise tail)
unmask_payload_inplace(payload_bytes, payload_len, mask_key);
```

### Handshake Key Calculation
```cpp
// Computes Sec-WebSocket-Accept from Sec-WebSocket-Key
std::string accept = compute_accept_key(client_key);

// Builds the full HTTP/1.1 101 Switching Protocols response string
std::string handshake_res = build_handshake_response(accept);
```
