Aegon is a high-performance C++23/C++26 asynchronous web and data framework. It is built for backend developers who need maximum throughput with modern C++: coroutines with `co_await`, zero-allocation hot paths, and a thread-per-core architecture powered by Linux `io_uring` (with epoll and IOCP fallbacks). Version 0.2.1 is authored by Uday Khare and distributed under the MIT license.

## Key features

Aegon provides a complete stack for building APIs, real-time services, and data-driven backends:

- **HTTP/1.1, HTTP/2, and HTTP/3 over QUIC** with TLS 1.3 and ALPN negotiation
- **io_uring thread-per-core** event loops on Linux, with epoll fallback and IOCP on Windows
- **Server-Sent Events (SSE)** and **WebSockets** for real-time streaming
- **HTTP client** with connection pooling, HTTP/2, and HTTP/3 support
- **Compile-time ORM** for PostgreSQL and SQLite with relations, transactions, and query caching
- **Redis client** supporting standalone, Sentinel, Cluster, Streams, Lua, and distributed locking
- **In-memory store** (LRU + TTL) for high-speed caching without external dependencies
- **JWT signing and verification** with JWKS support and token denylisting
- **DTO validation** with automatic RFC 7807 Problem Details responses
- **Dependency injection** via a zero-lock `ServiceRegistry` with freeze semantics
- **SIMD-accelerated routing** with stack-allocated path parameters

## Performance highlights

Aegon is benchmarked against industry-leading frameworks under strict hardware isolation. On identical Linux hardware (2 physical cores for the server, 4 for the load generator), Aegon leads every measured workload.

### HTTP/1.1 plaintext

| Framework | Throughput | vs Aegon |
| :-- | :-- | :-- |
| **Aegon (C++26, io_uring)** | **547,145 req/s** | Baseline |
| Swerver (Zig) | 468,613 req/s | -14.4% |
| Actix-web (Rust) | 400,128 req/s | -26.9% |
| Drogon (C++17) | 388,383 req/s | -29.0% |
| Fiber (Go) | 352,123 req/s | -35.6% |

## Why Aegon is fast

1. **True asynchronous io_uring ring batching**: Aegon bypasses epoll syscall overhead with multishot accept and recv submissions, yielding measurably higher throughput than epoll-based frameworks.
2. **Zero-allocation hot path**: Stack-allocated route parameters (`std::array<std::pair<std::string_view, std::string_view>, 8>`) and first-byte static child pruning in the Radix tree eliminate dynamic allocations during routing.
3. **Compile-time JSON with Glaze**: Struct serialization happens directly into existing buffer memory without runtime intermediate node trees.
4. **Symmetric-transfer coroutines**: `core::Task<T>` uses symmetric coroutine transfer to prevent stack overflow during continuous network packet processing.
