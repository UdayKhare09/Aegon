Aegon supports multiple installation methods: building from source with CMake, installing a prebuilt Arch Linux package from GitHub releases, or integrating via vcpkg.

## Prerequisites

Aegon requires a compiler and toolchain with C++23 support. The project also uses several system and third-party libraries.

### Compiler and toolchain

- **CMake** 3.20 or newer
- **C++23 capable compiler**:
  - GCC 13 or newer
  - Clang 17 or newer
  - MSVC with `/std:c++latest` (Visual Studio 2022 17.8+)
- **Ninja** (recommended generator)
- **Git**

### Dependencies

Aegon links against the following libraries. Most are required; some are optional depending on which CMake targets you use.

| Dependency | Required for | Notes |
| :-- | :-- | :-- |
| Threads | All targets | POSIX or Windows threads |
| glaze | `Aegon::config`, `Aegon::orm`, `Aegon::http` | Compile-time JSON reflection |
| OpenSSL | `Aegon::http`, `Aegon::redis` | TLS 1.3, ALPN, JWT signing/verification |
| PostgreSQL libpq | `Aegon::orm` | PostgreSQL driver |
| SQLite3 | `Aegon::orm` | SQLite driver |
| libdeflate | `Aegon::http` | HTTP compression |
| nghttp2 | `Aegon::http` | HTTP/2 framing |
| nghttp3 | `Aegon::http` | HTTP/3 over QUIC |
| ngtcp2 + ngtcp2_crypto_ossl | `Aegon::http` | QUIC transport |
| liburing | `Aegon::core` on Linux | io_uring backend (Linux only) |

On Linux, install system dependencies with your package manager. For example, on Arch Linux:

```bash
sudo pacman -Syu --needed base-devel cmake ninja gcc git \
  liburing openssl sqlite postgresql-libs \
  libnghttp2 libngtcp2 libnghttp3 libdeflate glaze
```

On Ubuntu/Debian:

```bash
sudo apt-get update && sudo apt-get install -y \
  build-essential cmake ninja-build git \
  liburing-dev libssl-dev libsqlite3-dev libpq-dev \
  libnghttp2-dev libngtcp2-dev libnghttp3-dev libdeflate-dev
```

<Note>
  The `glaze` package may not be available in all distribution repositories. If it is missing, build and install glaze from source first, or use vcpkg which handles it automatically.
</Note>

## Build from source

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/udaykhare09/aegon.git
    cd aegon
    ```
  </Step>
  <Step title="Configure with CMake">
    ```bash
    cmake -B build -G Ninja \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_INSTALL_PREFIX=/usr/local
    ```

    Optional build flags:

    | Option | Default | Description |
    | :-- | :-- | :-- |
    | `AEGON_BUILD_TESTS` | `ON` | Build the test suite and register tests with CTest |
    | `AEGON_BUILD_SAMPLES` | `ON` | Build sample applications (requires `aegon_http`, `aegon_orm`, `aegon_redis`) |
    | `AEGON_BUILD_BENCHMARKS` | `ON` | Build benchmark harnesses |
  </Step>
  <Step title="Build">
    ```bash
    cmake --build build -j$(nproc)
    ```
  </Step>
  <Step title="Install">
    ```bash
    sudo cmake --install build
    ```

    This installs libraries, headers, and CMake package files to the prefix you configured. After installation, other projects can use:

    ```cmake
    find_package(Aegon REQUIRED)
    target_link_libraries(my_app PRIVATE Aegon::http)
    ```
  </Step>
</Steps>

## Arch Linux package

Aegon provides an official `PKGBUILD` in `packaging/arch/`. GitHub releases also publish prebuilt `.pkg.tar.zst` packages for tagged versions.

### Build the package locally

```bash
cd packaging/arch
makepkg -si
```

This builds Aegon in a clean chroot and installs it to your system.

### Install from GitHub releases

The release workflow (`.github/workflows/release.yml`) builds the Arch package in a container and attaches the resulting `.pkg.tar.zst` to each GitHub release. Download the latest release asset and install it with:

```bash
sudo pacman -U aegon-0.2.1-1-x86_64.pkg.tar.zst
```

## vcpkg port

Aegon includes a vcpkg port in `packaging/vcpkg/`. You can add it to your vcpkg registry or overlay ports.

The `vcpkg.json` declares the following dependencies:

```json
{
  "name": "aegon",
  "version-semver": "0.2.1",
  "dependencies": [
    "openssl",
    "sqlite3",
    "libpq",
    "nghttp2",
    "ngtcp2",
    "nghttp3",
    "libdeflate",
    "glaze"
  ]
}
```

The `portfile.cmake` configures Aegon with tests, samples, and benchmarks disabled, then installs and fixes up the CMake config:

```cmake
vcpkg_cmake_configure(
    SOURCE_PATH "${SOURCE_PATH}"
    OPTIONS
        -DAEGON_BUILD_TESTS=OFF
        -DAEGON_BUILD_SAMPLES=OFF
        -DAEGON_BUILD_BENCHMARKS=OFF
)
vcpkg_cmake_install()
vcpkg_cmake_config_fixup(PACKAGE_NAME Aegon CONFIG_PATH lib/cmake/Aegon)
```

## Running tests

Aegon uses CTest for its test suite. Some tests require live services (PostgreSQL and Redis) provided by `docker-compose.test.yml`.

### Run unit tests (no external services)

```bash
cd build
ctest --output-on-failure -R "test_(version|simd_string|logger|foundational_types|dto_validation|error_handling|radix_router|simd_router|middleware|access_log|cors|security_headers|cookie|jwt|auth_middleware|rbac_guard|jwks|compress|http_client|service_registry|websocket|forms|config)"
```

### Run integration tests with Docker services

```bash
docker compose -f docker-compose.test.yml up -d
# Wait for health checks to pass, then:
cd build
ctest --output-on-failure
```

The `docker-compose.test.yml` spins up:

- PostgreSQL 17 (user `aegon`, database `aegon_test`)
- Redis standalone (port 6379)
- Redis Sentinel topology (ports 6380, 6381, 26379)
- Redis Cluster (ports 7000-7005)

## Platform support

| Platform | Engine | Status |
| :-- | :-- | :-- |
| Linux 6.1+ | io_uring (preferred), epoll fallback | Fully supported |
| Linux \< 6.1, Docker, WSL2 | epoll | Fully supported |
| Windows | IOCP | Supported |
| macOS / BSD | kqueue (planned) | Not yet implemented |

On Linux, Aegon automatically probes for `io_uring` and falls back to `epoll` if it is unavailable or restricted. On Windows, the build uses IOCP and links `ws2_32`, `mswsock`, and `ntdll`.
